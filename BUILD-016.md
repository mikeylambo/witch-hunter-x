# Witch Hunter // X — Build 0.16 Pre-Production Complete

## What this branch proves
- Four hunters are always simultaneously present in gameplay.
- P1 is keyboard; P2–P4 are CPU companions when no pads are connected and seamlessly become local human seats when pads appear.
- Shared camera, positional/overlay combat states, Handoffs, revives, team survival, individual X Gauge/Installs and team Style are all operating in the same simulation.
- Riven / Vale / Knox / Morrow names and unique verbs are preserved; no literal DMC character naming exists in production-facing code/UI.
- NEXUS hub -> party -> mission board -> comic briefing -> mission -> results -> progression loop is represented.
- Four campaign Incidents represent Magical Girl, Coven, Siren and Succubus Witch pressure.
- Persistent low-slot buildcraft exists: shared passive, hunter identity mods, techniques, tactical consumables.
- Campaign progression unlocks incidents sequentially.
- Bosses use Break-gated positional control and multi-phase behavior.

## Intentional stop line
The remaining highest-value work is no longer honestly answerable with primitives:
- real hunter meshes, rigs and animations
- actual Arsenal weapons, TK hand constructs, Morrow robot chassis
- Vale spatial-cut authored VFX
- Witch silhouettes / transformation animation
- authored environments and traversal spaces
- proper hitboxes tied to animation frames
- VO / music / SFX / comic art
- final UI typography and art direction
- real tuning through local 2–4 player playtests

Character Frame should be integrated with the first production model rather than expanded abstractly before a model exists.
